## Attribution Footer — Required on Every Client Site

Every site Anchor Digital builds carries a credit link in the footer. No exceptions, no client sign-off needed — it's standard agency practice and part of the deal.

### Structure

Client copyright on the **left**. Anchor Digital credit on the **right**, always including the mark.

```html
<footer class="site-footer">
  <p class="footer-copyright">&copy; 2026 [Client Name]. All rights reserved.</p>
  <a class="footer-credit"
     href="https://anchordigitalco.com"
     target="_blank"
     rel="noopener">
    <svg class="footer-mark" viewBox="364 171 615 312" fill="currentColor" aria-hidden="true">
      <g id="mark-left"><path d="..."/></g>
      <g id="mark-right"><path d="..."/></g>
    </svg>
    <span>Built by Anchor Digital</span>
  </a>
</footer>
```

### Rules

- Domain is **`https://anchordigitalco.com`**. This is the confirmed live domain — not a placeholder, not `.co`.
- Opens in a **new tab** (`target="_blank"` + `rel="noopener"`). Never navigate the client's visitor away from their own site.
- **Never** add `rel="nofollow"`. These links are legitimate backlinks to Anchor Digital and should pass authority.
- The credit is **smaller and quieter** than the client's copyright — typically one step down in size, 60–70% opacity, full opacity on hover. It must never compete with the client's brand.
- Copyright year is the **build year**, hardcoded. Do not use a JS auto-updating year.
- Desktop: left/right on one row. Mobile: stacked and centered, client copyright first.
- The credit inherits the site's own type stack. Do not import a separate font for it.
- Hover state required on the link (opacity or underline). No `transition-all`.

### The Mark — Always Included, Not Optional

The Anchor Digital mark sits beside the credit text on every client site. Standard, not a stylistic choice.

- **File:** `brand_assets/anchor-digital-mark.svg`. Copy into every new project alongside the client's own brand assets.
- **SVG only.** Never a PNG or JPG. Never recreate the mark by hand.
- **viewBox is `364 171 615 312`** — the mark is wide, roughly **1.97:1**, not square. Never set equal width and height; it will distort. Set height and let width follow, or compute width as `height × 1.971`.
- Mark height matches the credit text's cap height, roughly **14–16px** → **~28–31px wide**. It is a bullet point, not a logo placement.
- Root carries `fill="currentColor"`, so the mark inherits the footer text color automatically. One file works on light and dark grounds — do not create separate color versions, do not add a `fill` or `color` override.
- Inner groups `#mark-left` and `#mark-right` exist for animation on Anchor Digital's own site. On client sites they are structural only — do not animate or split them.
- Inline the SVG in the markup rather than using `<img>`, or `currentColor` will not resolve.
- **Fallback only:** if `brand_assets/anchor-digital-mark.svg` is genuinely missing from a project, use text-only and flag it to Jackson. Never substitute a raster image.

### First-Party Projects (Anchor Digital's own site)

The attribution clause does **not** apply. Do not add a "Built by Anchor Digital" credit to Anchor Digital's own site — it would link to itself.

The footer carries the copyright line only:

```html
<footer class="site-footer">
  <p class="footer-copyright">&copy; 2026 Anchor Digital. All rights reserved.</p>
</footer>
```

Everything else in this file still applies — GitHub accounts, git workflow, stack decisions, per-project setup.

Note: the agency site is the destination for every attribution backlink from every client site. Treat it as the permanent SEO anchor — the URL structure should not change after client sites start pointing at it.

## Stack Decisions

Decide the stack **before** writing any code.

- **Astro + Tailwind + Vercel** → informational sites: portfolios, local business, blogs, landing pages.
- **Next.js + Supabase + Stripe + Vercel** → anything with user accounts, payments, orders, or real-time data.
- **Sanity CMS** → added when the client needs to self-manage content without touching code.
- **Square** → restaurant clients already using it as their POS.

The rule: if a user logs in and sees *their* data, or money moves, it's an app — not a static site.

Hosting is **Vercel** for all new projects.
